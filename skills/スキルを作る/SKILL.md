# スキルを作る

9段で進みます。1段ごとに止まり、承認をもらってから次へ進みます。
まとめて進めません。本文を書いてから形を直す往復を無くすための手順です。

## 目次

1. 言い換え（ユーザーの言葉を1行にする）
2. 完了条件（ユーザーが1文書き、確かめられる形に詰める）
3. 使う場面（呼び出す言葉を決める）
4. 新規か追加か（既存のスキルを調べて問い合わせる）
5. 矛盾の点検（ルールやほかのスキルと反対のことを書いていないか）
6. 置き場所（.claude/skills の中のフォルダ名）
7. 構成（見出しの一覧だけ見せる）
8. 本文（スキルの書き方に従って書く）
9. 点検（形式と、スキルとして読み込まれたか）

## 1. 言い換え（ユーザーの言葉を1行にする）

言われたことを1行に言い換えて、合っているか確かめます。
ユーザーの言葉は音声入力のことが多く、言い直しや省略が混ざります。
言い換えるときも、ユーザーの言葉をなるべくそのまま使います。別の言葉に置き換えると、読みづらくなります。

止まります。承認をもらってから次へ進みます。

## 2. 完了条件（ユーザーが1文書き、確かめられる形に詰める）

「完了条件を1文でお願いします」と促します。雑でかまいません。
受け取った1文を、確かめられる点に詰め直して見せます。
完了条件をユーザーが先に書くのは、できたかどうかを確かめる主導権をユーザーの側に置くためです。

止まります。承認をもらってから次へ進みます。

## 3. 使う場面（呼び出す言葉を決める）

何と言われたらこのスキルを使うかを決めます。description の③に書く言葉になります。
Claude から勝手に始めないスキルなら、そのことも書きます。

止まります。承認をもらってから次へ進みます。

## 4. 新規か追加か（既存のスキルを調べて問い合わせる）

同じ話のスキルが無いか探します。

```
ls .claude/skills/ ~/.claude/skills/
```

新しく作るか、既存のスキルに足すかを問い合わせます。勝手に決めません。
1つのスキルに別の話が2つ入ると、名前で中身が言えなくなります。名前で言えるかどうかで決めます。

止まります。承認をもらってから次へ進みます。

## 5. 矛盾の点検（ルールやほかのスキルと反対のことを書いていないか）

同じ話題のルールとスキルを読み、反対のことを書いていないか確かめます。
矛盾があると、Claude はどちらかを適当に選びます。
見つけたら、その場でユーザーに報告します。黙って片方を直しません。

止まります。承認をもらってから次へ進みます。

## 6. 置き場所（.claude/skills の中のフォルダ名）

ユーザーが自分で読めるように、プロジェクトの中に置きます。

```
.claude/skills/<スキル名>/SKILL.md
```

フォルダ名がスキル名になります。名前だけで中身が言えるか確かめます。

止まります。承認をもらってから次へ進みます。

## 7. 構成（見出しの一覧だけ見せる）

見出しを並べて見せます。本文は書きません。
骨組みを先に確かめます。本文まで書いてから形を直すと、往復が増えます。

止まります。承認をもらってから次へ進みます。

## 8. 本文（スキルの書き方に従って書く）

書き方は、同じフォルダの `スキルの書き方.md` に従います。
日付つきの経緯の引用は削ります。意味を伝えるユーザーの言葉は、そのまま残します。

止まります。承認をもらってから次へ進みます。

## 9. 点検（形式と、スキルとして読み込まれたか）

次の3つを確かめて報告します。

- `#` の見出しが1つで、フォルダ名と同じ
- 目次と見出しの番号がそろい、どの見出しにもかっこがある
- Claude Code のスキルの一覧に、新しいスキルが出ている

止まります。承認をもらってから次へ進みます。最後の段なので、この承認で完了です。
