# 詳細学習モード

1段ずつ説明し、ユーザーが納得したら1か所だけ直して、git の差分を見てもらいます。
差分を見ることで覚えます。まとめて進めません。

## 目次

1. 使う場面（とても重要なもの、難しいもの、学習のときだけ）
2. 理由（字面を読んで ok と言っても覚えていない）
3. 段の分け方（知っているものは大きく、難しいものは小さく）
4. 1段の回し方（コミット、編集、差分、コミットのループ）
5. 準備（git の外にあるものは、先に git に入れる）
6. 禁止（一気に説明しない、一気に直さない）
7. ほかの決まりとの関係（このモードの中だけ、コミットを言われなくても行う）

## 1. 使う場面（とても重要なもの、難しいもの、学習のときだけ）

このモードを作った人の言葉です。

> 「このやり方は毎回するわけではないです」

> 「このファイルのように非常に重要なものを修正する時のみ行います。あるいは私にとって非常に難しいファイルの場合です」

> 「ファイルに限らず、何らかの学習にも使います」

ユーザーが「詳細学習モードで」と言ったときだけ使います。Claude から勝手には始めません。

## 2. 理由（字面を読んで ok と言っても覚えていない）

> 「今あなたが、一段階から説明して進めている内容はすべて忘れています。私は理解していないです」

> 「スクロールが進んで一段目はなんだったかな二段目はなんだったかな思い出そうとしても何も覚えていないです」

> 「それは字面だけを読んで納得して ok というふうに進んでいるだけだからです」

> 「その差分を見て比較して私が初めて学習が起こります。記憶に定着するという意味です」

説明を読んで承認しても、覚えたことにはなりません。直した差分を見て、はじめて覚えます。

## 3. 段の分け方（知っているものは大きく、難しいものは小さく）

> 「まずあなたが、提示して小さい部分的なステップに分割する。私が認識できる」

> 「その時の状態によります。私がもともと知っているものであれば粒度は大きくなるが、難しいものであれば粒度は小さくなる」

分からないと言われたら、段を小さくします。

## 4. 1段の回し方（コミット、編集、差分、コミットのループ）

> 「ひとつの納得ができた後、ファイルを修正します。このファイルのどこをどのように修正されたかは、ギットの差分で確認できます」

> 「コミットして編集する。差分を見る。差分を見ることによって、私の学習効果が高くなる。そしてコミットするのループになります」

1. 1段だけ説明します。ユーザーの言葉を使い、別の言葉に置き換えません。
2. ユーザーが納得するまで待ちます。ここで止まります。
3. 編集の前にコミットします。
4. その段の1か所だけを編集します。
5. git の差分をチャットに貼ります。
6. ユーザーが差分を見ます。ここで止まります。
7. コミットして、次の段へ進みます。

## 5. 準備（git の外にあるものは、先に git に入れる）

git の外にあるものをこのモードで直すときは、先に git に入れます。
git の設定を変えることになるので、入れ方を示して承認をもらってから行います。

ワークスペースの一番上に git を作り、`.gitignore` で1ファイルだけを入れる形は使いません。
Claude Code の検索は `.gitignore` に従うので、一番上から検索しても、ほかのファイルが見つからなくなります。
git の本体はワークスペースの外に置き、`git --git-dir=<git の本体> --work-tree=<ワークスペース>` の形で扱います。

## 6. 禁止（一気に説明しない、一気に直さない）

> 「一気に進めても意味がないです」

> 「一気に全部説明しないでください」

> 「そんな風に人間が一気に理解できると思わないで下さい」

- 複数の段をまとめて説明しません。
- 全部説明してから、最後に一気に直しません。
- 前の段を番号だけで指しません。ユーザーは前の段を覚えていない前提で書きます。

## 7. ほかの決まりとの関係（このモードの中だけ、コミットを言われなくても行う）

「コミットはユーザーが言ったときだけ行う」という決まりがあっても、このモードの中だけは、4節のループのとおり、言われなくてもコミットします。
モードを出たら、元の決まりに戻ります。
