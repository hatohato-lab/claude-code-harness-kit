# セッション情報

どのセッションで呼ばれても、呼んだセッション自身のことだけを表1つで出します。
ほかのセッションの一覧は「セッションALL」スキルを使います。

## 目次

1. IDの取り方（自分のセッションIDを知る）
2. 情報の取り出し（生ログから取る項目）
3. 呼び出しの番号（ほかのセッションから指定するとき）
4. 作業の概要（その日を時間帯で区切る）
5. 表の形（列と並び順）
6. 禁止（ほかのセッションを見ない、保存しない）

## 1. IDの取り方（自分のセッションIDを知る）

1. スクラッチパッドのパスに入っています（`.../<セッションID>/scratchpad` の形）。
   会話に貼られた画像のパスにも、同じIDが入っていることがあります。
2. 見つからなければ、ユーザーに「このセッションIDを教えてください」と1行で聞きます。
   更新時刻がいちばん新しいログを選ぶ、という推測はしません。

## 2. 情報の取り出し（生ログから取る項目）

作業フォルダで、プラグインの `scripts/session_log.py` を実行します。
このスキルのフォルダから2つ上の階層にあります。`python` が無ければ `python3` を使います。

```
python <プラグインのフォルダ>/scripts/session_log.py info <自分のセッションID>
```

名前が無ければ「未設定（/rename で付ける）」と出ます。

## 3. 呼び出しの番号（ほかのセッションから指定するとき）

`ListAgents` が使える環境なら、1回呼びます。結果の1行目に出る番号が、このセッションの番号です。
ほかのセッションへ SendMessage で名乗るとき、この番号を使います。使えない環境では、この行を省きます。

## 4. 作業の概要（その日を時間帯で区切る）

同じ話題を違う時間にもう一度やることがあるので、話題でまとめず、時間順に並べます。
同じ話題が2回出てきたら、まとめずに2行書きます。

```
python <プラグインのフォルダ>/scripts/session_log.py msgs <自分のセッションID>
```

今日の発言が1件も無ければ、直近で発言があった日を指定し、概要の見出しにその日付を書きます。

出た時刻を、話題の切れ目でまとめて1行にします。書き方は4点です。

- 1行の形は `09:10〜10:40  ブログの図と本文を作り直し`
- 時刻は実測値。1件だけの話題は開始時刻だけ書く
- 内容は25字前後の具体名。「作業」「対応」「確認」のような一般語は使わない
- 6行以内。細かい往復は1つの時間帯にまとめる

細かい表が要るときは「本日作業」スキルを使うので、ここでは作りません。

## 5. 表の形（列と並び順）

```
名前            設計_0921
セッションID    99993af3-ac36-415e-b3d8-054b7ae00c5b
生ログ          ~/.claude/projects/.../99993af3-....jsonl
開始            2026-09-20 17:47
最終更新        2026-09-21 01:05
圧縮回数        0 回
ログの大きさ    4.8 MB / 1,210 行
モデル          claude-opus-5-5
呼ぶときの番号  00-c5
```

生ログのパスは、この表の下に単独のコードブロックでも出します。ワンクリックでコピーするためです。

そのあとに、概要を時間順で出します。

```
概要（2026-09-21）
09:10〜10:40  ブログの図と本文を作り直し
11:00〜11:40  サイトのページ27件を修正
```

## 6. 禁止（ほかのセッションを見ない、保存しない）

- ほかのセッションの生ログを開きません。
- ファイルに保存しません。チャットに出すだけです。
- 表の前後に説明を書きません。
- 取れなかった項目は「不明」と書きます。推測で埋めません。
