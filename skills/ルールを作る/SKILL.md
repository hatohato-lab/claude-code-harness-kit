# ルールを作る

9段で進みます。1段ごとに止まり、承認をもらってから次へ進みます。
まとめて進めません。本文を書いてから形を直す往復を無くすための手順です。

## 目次

1. 主題の確認（ユーザーの言葉を1行に言い換える）
2. 失敗の特定（そのルールが無いせいで何が起きたか）
3. 新規か追加かの判断（必ず問い合わせる）
4. 矛盾の点検（反対のことを書いたルールを探す）
5. ファイル名の決定（分類、番号、P の有無）
6. 構成の確認（見出しの一覧だけ）
7. 本文の執筆（ルールの書き方に従う）
8. 形式の点検（7つのコマンドを回す）
9. 出す直前の自己確認（チャットの案にも適用する）

## 1. 主題の確認（ユーザーの言葉を1行に言い換える）

言われたことを1行に言い換えて、合っているか確かめます。

ユーザーの言葉は音声入力のことが多く、言い直しや省略が混ざります。
そのまま書き起こすと意図がずれ、要約しすぎると核心が落ちます。

止まります。合っていると言われるまで次へ進みません。

## 2. 失敗の特定（そのルールが無いせいで何が起きたか）

そのルールが無いせいで、実際に何が起きたかを1つ挙げます。

失敗が無いなら、ルールにしません。
指示が無くても正しくできることを書くと、ほかのルールが埋もれます。

例: 2つのセッションが「47件の依頼は着手していません」とだけ書いて着手の許可を求め、何を直すのかが1件も分からなかった。

止まります。承認をもらってから次へ進みます。

## 3. 新規か追加かの判断（必ず問い合わせる）

既存のルールを調べ、同じ話が無いか探してから、ユーザーに問い合わせます。

```
grep -ln "<主題の語>" .claude/rules/*.md
```

問い合わせる形は2択です。

- 新しいファイルを作る
- 既存の `<ファイル名>` の `<何節>` に足す

どちらかを勝手に決めません。この段は省略しません。

1つのファイルに別の話が2つ入ると、ファイル名で中身が言えなくなります。名前で言えるかどうかで決めます。

止まります。承認をもらってから次へ進みます。

## 4. 矛盾の点検（反対のことを書いたルールを探す）

同じ話題を扱ったルールがほかにあれば、反対のことを書いていないか読みます。

矛盾があると、Claude はどちらかを選んで進み、もう片方は効かなくなります。
どちらが効かなくなるかは分かりません。

例: あるルールは「ファイルはワークスペースの外に置かない」、別のルールは「作業の出力は一時フォルダに出す」と書いていた。

見つけたら、その場でユーザーに報告します。黙って片方を直しません。

止まります。承認をもらってから次へ進みます。

## 5. ファイル名の決定（分類、番号、P の有無）

形は次のとおりです。

```
【分類】_番号_名前.md
【分類】_番号_P_名前.md
```

分類は、その環境で決めたものを使います（例: 安全、整理、見た目、進め方）。
番号は分類ごとの連番です。欠番は詰めません。詰めると、会話で言った番号とずれます。

`P` は paths を付けるときだけ入れます。paths は、その場所を触るときだけ読み込ませたい場合に使います。

ファイル名だけで中身が言えるか確かめます。言えないなら、3段の判断に戻ります。

止まります。承認をもらってから次へ進みます。

## 6. 構成の確認（見出しの一覧だけ）

見出しを並べて見せます。本文は書きません。

```
1. 原則（〜する約束）
2. 失敗例（〜した経緯）
3. 手順（〜の決まり◯点）
```

骨組みを先に確かめます。本文まで書いてから形を直すと、往復が増えます。

止まります。承認をもらってから次へ進みます。

## 7. 本文の執筆（ルールの書き方に従う）

書き方は、同じフォルダの `ルールの書き方.md` に従います。

残すのは3つです。失敗の中身、なぜそうするかの理由、ユーザーの言葉そのままです。

書かないのは、作成日の行、題名の飾り、参照の節、`[[ ]]` のリンク、区切り線、途中に挟む出典のURLです。

止まります。承認をもらってから次へ進みます。

## 8. 形式の点検（7つのコマンドを回す）

書き終えたら、ルールのフォルダで7つを回します。`ルールの書き方.md` の8節と同じものです。

```
grep -n "^作成：" *.md --exclude=README.md
```

```
grep -n "^## [0-9]*\. .*20[0-9][0-9]-" *.md --exclude=README.md
```

```
grep -n "^## [0-9]*\. 参照" *.md --exclude=README.md
```

```
grep -on "\[\[[^]]*\]\]" *.md --exclude=README.md
```

```
grep -c "^-\{10,\}" *.md --exclude=README.md | grep -v ":0"
```

```
grep -n "^## [0-9]*\. [^（]*$" *.md --exclude=README.md
```

```
grep -c "^# " *.md --exclude=README.md | grep -v ":1"
```

7つとも何も出なければ整っています。

止まります。承認をもらってから次へ進みます。

## 9. 出す直前の自己確認（チャットの案にも適用する）

見出しを出す前に、左が名詞か、かっこに中身が入っているかを確かめます。

「何の話か」「どうするか」「まとめ」「やること」は口語で、名詞ではありません。

この確認は、チャットに出す案にも適用します。
ファイルに書くときだけの決まりだと扱うと、案の段階で形が崩れます。

止まります。承認をもらってから次へ進みます。最後の段なので、この承認で完了です。
