# ルールの書き方

ルールをブラックボックスにせず、人が自分で読んで直せる状態を保つための書き方です。

## 目次

1. 置き場所（.claude/rules に1ファイル1ルール）
2. ファイル名（分類、番号、P の3つで作る）
3. 読み込む条件（paths を付けると場所を限定できる）
4. 見出しの書き方（概念＋かっこの説明）
5. 番号と目次（リンクは付けない）
6. 残すもの（判断を変えるものだけ）
7. 削るもの（判断を変えないものは全部）
8. 点検のしかた（ルールが増えたら回す7つのコマンド）

## 1. 置き場所（.claude/rules に1ファイル1ルール）

ルールは `.claude/rules` に置きます。1つのルールが1ファイルです。

paths の無いルールは、Claude Code が会話の最初に自動で読み込みます。

## 2. ファイル名（分類、番号、P の3つで作る）

形は次のとおりです。

```
【分類】_番号_名前.md
【分類】_番号_P_名前.md
```

分類は、その環境で決めた数個にします。
番号は分類ごとの連番です。欠番が出てもそのままにします。番号を詰め直すと、過去の会話で言った番号とずれます。

`P` は paths が付いているものだけに入れます。3節を見てください。

## 3. 読み込む条件（paths を付けると場所を限定できる）

paths が無いルールは、会話の最初に必ず読み込まれます。
paths があるルールは、その場所のファイルを触るときだけ読み込まれます。

書き方はファイルの先頭です。

```
---
paths:
  - "src/**"
---
```

paths を付けたら、ファイル名にも `_P_` を入れます。一覧で、常に読むものと場所を限定するものを見分けるためです。

## 4. 見出しの書き方（概念＋かっこの説明）

見出しは「概念（説明）」の形にします。

```
## 3. 手順（表のタイトルの書き方5点）
```

左の「手順」で何の話かが一瞬で分かります。右のかっこで、何件あるか、どういう内容かが分かります。

左だけを縦に拾い読みすれば全体像がつかめて、必要なところだけかっこの中を読めます。

悪い例は「守ること」「理由」「関連」「まとめ」です。中を読まないと何の話か分かりません。

## 5. 番号と目次（リンクは付けない）

見出しに `1.` から順に番号を振ります。
先頭に目次を置き、見出しをそのまま並べます。リンクは付けません。

見出しに id を付けないビューアでは、押しても飛ばないリンクが混乱のもとになるためです。

## 6. 残すもの（判断を変えるものだけ）

- 実際に起きた失敗の中身（抽象的な注意より効く）
- なぜそうするかの理由（AI が形を変えたくなったときに止まる材料になる）
- ユーザーが言った言葉そのまま（言い換えると意図がずれる）

例: 「私が言っているのは文字の量ではなくてスクロールの量です」。
この一言があると、短く書けば済む話ではないと伝わります。

## 7. 削るもの（判断を変えないものは全部）

基準は1つです。それを読んで、AI の判断か人の判断が変わるかどうかです。変わらないなら消します。

- ファイル冒頭の「作成：...」の行（git の履歴で追える）
- 見出しのかっこに入れた日付や「★追加」の印
- 題名の「（全プロジェクト共通・厳守）」のような飾り（全部に付いていて区別にならない）
- 「参照（関連するルール○件）」の節（別のルールを開く手間が増えるだけ）
- `[[ルール名]]` の形のリンク（改名すると開けなくなる）
- 区切り線（見出しで区切れている）
- 同じことを2つの節で説明している箇所（1つにまとめる）
- 見出しに書いたことの、本文での繰り返し

6節と7節の境目は、日付か中身かで分かれます。
「ある日に6件を片づけた」の日付は消し、「手順を飛ばして6件を片づけた」は残します。

Anthropic も、1行ごとに「この行を消したら Claude は間違えるか」を問い、間違えないなら消すよう勧めています。

## 8. 点検のしかた（ルールが増えたら回す7つのコマンド）

新しいルールを足したときは、ルールのフォルダで次を回します。
`--exclude=README.md` は、README 自身の例文を拾わないために付けます。

```
grep -n "^作成：" *.md --exclude=README.md
```

```
grep -n "^## [0-9]*\. .*20[0-9][0-9]-" *.md --exclude=README.md
```

```
grep -n "^## [0-9]*\. 参照" *.md --exclude=README.md
```

```
grep -on "\[\[[^]]*\]\]" *.md --exclude=README.md
```

```
grep -c "^-\{10,\}" *.md --exclude=README.md | grep -v ":0"
```

```
grep -n "^## [0-9]*\. [^（]*$" *.md --exclude=README.md
```

```
grep -c "^# " *.md --exclude=README.md | grep -v ":1"
```

上から順に、作成日、見出しの日付、参照の節、リンク、区切り線、かっこ抜けの見出し、`#` の重複を見ています。
何も出なければ整っています。

目次と見出しの番号がそろっているかは、目で見ます。ずれていたら見出しから作り直します。
